## Блокирующие

### Б1. `putPixels` с `replace: true` на каждой полосе стирает ранее записанные полосы

- **Где:** `src/plugin/ps-bridge.js:787–794` (`writeStrip`), строка 791.
- **Проблема.** Результат пишется полосами примерно по 1 Мп, и каждый вызов идёт с `replace: true`. Документация Adobe (`ps-reference/media/imaging.md`, параметр `replace`): «If true, then existing pixels in the layer are discarded before adding new pixels. If false, then the new pixels are added to the existing pixel content in the layer». Отбрасываются существующие пиксели **слоя**, а не только области записи.
- **Сценарий.** Документ 6000×4000, полоса 166 строк, 25 полос. После «Применить» в слое «Halation» остаются только последние 16 строк (y = 3984…3999), остальное прозрачно. Ошибки нет, панель пишет «Готово».
- **Почему тесты проходят.** Поддельный `putPixels` (`test/helpers/fake-photoshop.js:263–288`) параметр `replace` не читает и всегда пишет только в прямоугольник.
- **Исправление.**
  - В `writeStrip` передавать `replace: false`. Слой только что создан и пуст, полосы не пересекаются, поэтому «добавить к существующему» даёт ровно записанные пиксели, включая полупрозрачные. Это верно при любом толковании параметра.
  - В поддельном `putPixels`: при `o.replace !== false` перед записью обнулять `l._store` целиком. Тогда тест «offset layer, trimmed strips» поймает возврат ошибки.
  - В чек-лист для Ильи: после применения слой «Halation» закрывает весь исходный слой, а не одну полосу внизу.

## Серьёзные

### С1. Предпросмотр «После» в режиме своей кривой рисует края источников неверно

- **Где:** `src/core/preview.js:156–177` (`proxyLinear`), `279–281` (кодирование в `renderPreview`).
- **Проблема.** Для блока копии считается средний линейный свет по текущей кривой, `L = f255 + (1 − f255)·LUT_in[код(M)]`, и он же кодируется обратно через `LUT_in`. Для размытия это правильно, для показа — нет: уменьшенная картинка на экране равна среднему от **закодированных** пикселей, а не коду от среднего света. При кривой со скачком 254→255 блок, где 255 занимает 25 % площади, получает свет около 0,25 и код 254–255, хотя на экране он должен выглядеть как код 141.
- **Сценарий (воспроизведён).** 2000×1500, фон 40, белая линия шириной 1 px, кривая ×30, сила 40. Полный результат, уменьшенный до копии: 141. `renderPreview(..., "after")`: 255. Ошибка 114 кодов; «До» при этом показывает 141. При переключении «До / После» все тонкие светлые детали и края источников резко утолщаются, хотя в настоящем результате они не меняются. В режиме sRGB расхождение не больше 2 кодов.
- **Исправление.** В `renderPreview` для видов `after` и `halo` разделить блок на две части:
  - `Lrest = LUT_in[код(M)]` (вернуть из `proxyLinear` вторым массивом);
  - `Orest = combine(phys, c, Lrest, field)`, затем дробный код `cr` обратным переводом по `LUT_in` (как в `encode`, но без округления);
  - свет экрана блока: `D = f255·1 + (1 − f255)·srgbToLinear(cr / 255)`;
  - выходной код: `linearToSrgb(D)·255` с тем же шумом.
  - Тест: сравнивать не только поля, но и закодированную картинку с уменьшенным полным результатом, кривая ×30, линия 1 px и край квадрата, допуск 3–4 кода.

### С2. Кэш предпросмотра не учитывает альфу отдельных пикселей: фантомный ореол у краёв прозрачности

- **Где:** `src/core/preview.js:46–62` (`push`), `236–237` (`previewFields`).
- **Проблема.** `f255` и `mean` копятся по всем пикселям блока независимо от альфы, а альфа хранится только средняя по блоку. Источник затем считается как `f255 · al`. Полный расчёт умножает на альфу каждый пиксель (`processor.js:107–111`), и прозрачный пиксель света не даёт.
- **Сценарий (воспроизведён).** Слой 2000×1200: слева непрозрачный код 30, справа α = 0 с RGB = 255, граница на x = 1001 (не кратна блоку 4). Полный расчёт не меняет ни одного байта. Предпросмотр «После» рисует у края ореол: 30 → 40. Значение 255 в RGB прозрачных пикселей — обычное содержимое, которое возвращает `getPixels` внутри обрезанных границ; при RGB = 0 ореола нет, но блоки на краю теряют свет (двойное ослабление альфой).
- **Исправление.** В `push` взвешивать вклад альфой `a = α / 255`:
  - `if (v === 255) { c255 += a; dx255 += a·DX; dy255 += a·dy; } else sum += lut[v]·a;`
  - копить `wsum[bi] += a`;
  - в `finish`: `f255 = c255 / wsum`, `mean = sum / (wsum − c255)`, `alpha = wsum / cnt` (при `wsum = 0` — нули).
  - Формулы `previewFields` (`part = f·al`, `L·al`) после этого дают в точности предумноженный свет.
  - Тест: слой с прозрачной половиной и RGB = 255 под ней — предпросмотр «После» равен «До».

### С3. При снятой галочке «Заменять прежний результат» новый результат оказывается под старым; после Undo связь с прежним результатом теряется

- **Где:** `src/plugin/ps-bridge.js:817–820` (`createResultLayer`), `608–620` (план), `970–973` (учёт пар).
- **Проблема 1.** Новый слой всегда ставится прямо над исходным (`move(src, PLACEBEFORE)`), то есть **под** прежний слой «Halation». Прежний результат — полное непрозрачное изображение и закрывает новый.
- **Сценарий 1.** Галочка снята. «Применить» (сила 30) → слой R1. Сила 60, «Применить» → слой R2 ложится между исходным и R1. На экране ничего не меняется, панель пишет «Готово». Тест `bridge.test.js:362–366` считает только число слоёв, порядок не проверяет, а комментарий в нём («added on top of the old one») описывает обратное.
- **Проблема 2.** `pairs` хранит только последний ID, а запись `resultSource` для удалённого слоя стирается (строка 971).
- **Сценарий 2.** Галочка включена. «Применить» → R1. «Применить» → R1 удалён, создан R2. Cmd+Z → R1 вернулся, R2 исчез. «Применить»: `pairs` указывает на R2, которого нет, `previousResultId = null`, R1 не удаляется, R3 ложится под R1 — снова ничего не видно. Если же активен R1, он больше не числится результатом и обрабатывается как обычный слой: ореол поверх ореола, без предупреждения.
- **Исправление.**
  - Хранить на исходный слой список ID результатов: `Map<sourceKey, number[]>`; записи `resultSource` не удалять (несуществующие ID отсеивает `existingLayerId`).
  - При замене удалять все существующие слои из списка.
  - Без замены ставить новый слой над верхним из существующих результатов этого источника: `layer.move(topExistingResult, PLACEBEFORE)`.
  - Тесты: порядок слоёв без замены; сценарий с откатом (в поддельном Photoshop вернуть удалённый слой и убрать созданный).

### С4. Режим «видимое изображение»: прежний результат попадает в источник

- **Где:** `src/plugin/ps-bridge.js:535–544` (план композита), `554–559`; `src/plugin/panel.js:536` (предпросмотр всегда с `replacePrevious: false`).
- **Проблема.** Композит читается через `getPixels` без `layerID`. Прежний слой «Halation» убирается из него только когда включена замена и ID есть в `pairs`.
- **Сценарии.**
  - Галочка снята, источник — видимое изображение: второе применение считает ореол по картинке, где ореол уже есть. Примечание панели говорит «эффект снова будет применён к видимому изображению», о двойном эффекте — ни слова.
  - Галочка включена, но предпросмотр строится с `replacePrevious: false`: копия для предпросмотра включает прежний результат, а «Применить» его сначала удалит. Предпросмотр и результат расходятся.
- **Исправление.** В режиме композита внутри той же модальной операции временно скрывать все существующие слои-результаты этого документа (`layer.visible = false`) на время чтения, затем возвращать видимость тем, что не удаляются. Делать это и в `buildPreview`. Если скрывать не хочется — блокирующее сообщение «сначала удалите или скройте слой Halation».

### С5. Ошибки `getPixels` молча превращаются в «пустые полосы», а итог объявляется успешным

- **Где:** `src/plugin/ps-bridge.js:705–718` (перехват), `940–943` (проход 2), `src/plugin/panel.js:688–693` (сообщение об успехе).
- **Проблема.** Любая ошибка `getPixels`, кроме отмены и «модальный режим занят», считается прозрачной полосой. Общая ошибка поднимается, только если пусты **все** полосы. `toleratedErrors` попадает лишь в скрытый блок диагностики.
- **Сценарии.**
  - Полоса 7 из 25 в проходе 1 падает из-за разовой ошибки (нехватка памяти, сбой диска подкачки). `had[7] = false`, её свет в базовую сетку не попал. В проходе 2 чтение удаётся: полоса обрабатывается и записывается, но ореол от её источников отсутствует во всём кадре. Статус — «Готово».
  - Та же полоса падает и в проходе 2 (`expectData` равен `false`): в слое результата остаётся прозрачная дыра высотой в полосу. Статус — «Готово».
  - В режиме композита и для непрозрачного слоя пустых полос не бывает вовсе, но правило действует и там.
- **Исправление.**
  - Терпеть ошибку только при `plan.mode === "layer"`.
  - В проходе 2: если `had[i] === false`, а данные пришли (`s2.hadData`), бросать ошибку «полоса изменилась между проходами».
  - Если после прохода 1 `stats.toleratedErrors > 0` и при этом есть полосы с данными выше и ниже ошибочной — бросать первую ошибку: прозрачной может быть полоса с краю области или целый промежуток, но не одиночная полоса из-за ошибки чтения. Минимальный вариант: при успехе с `toleratedErrors > 0` показывать в панели предупреждение со ссылкой на диагностику, а не «Готово».

### С6. Базовая сетка в полном разрешении до 4 Мп: 3 Мп считаются дольше, чем половина от 24 Мп

- **Где:** `src/core/processor.js:11` (`FULL_RES_MAX = 4000000`), `41–46` (`autoBaseLevel`).
- **Проблема.** До 4 Мп базовая сетка равна полному разрешению, и самая узкая гауссиана (σ ≈ 1,9 px) считается прямой свёрткой на всех пикселях.
- **Замер (`node --jitless`).** 2000×1500: всего 12,3 с, из них размытие 9,7 с. Тот же кадр с `baseLevel: 1`: 6,7 с; результат отличается не больше чем на 3 кода, отличий больше 1 кода — 79 значений из 9 млн, среднее 0,036 (уровень шума дизеринга). Для сравнения, 24 Мп по приложению C — 29,4 с при размытии 7,4 с. К тому же отдельный проход свёртки на 3 Мп длится 2–4 с без точки отмены.
- **Исправление.** Снизить `FULL_RES_MAX` до 1 000 000 (или выбирать уровень 1, когда у узкой гауссианы после поправки `σ² − 1 ≥ 0,3²·4`). Прогнать тесты центра масс, изотропии и независимости от разрешения на 1500–2000 px с уровнем 1.

## Мелкие

### М1. Флаг занятости ставится после `await`: двойной запуск

- **Где:** `src/plugin/panel.js:533–556` (`rebuildPreview`), `635–671` (`onApply` → `runApply`).
- **Сценарий.** Двойной щелчок по «Применить» (или щелчок в первые миллисекунды после показа панели, пока идёт `inspect` предпросмотра). Оба вызова проходят проверку `state.busy`, оба доходят до `executeAsModal`. Второй получает «модальный режим занят»; его `finally` вызывает `setBusy(false)` и включает кнопки, пока первая обработка ещё идёт, а статус ошибки затирает прогресс.
- **Исправление.** Ставить `state.busy = true` синхронно в начале `onApply` и `rebuildPreview` (до `await inspect`), снимать в `finally` того же вызова; `runApply` из окна подтверждения — с отдельной проверкой.

### М2. Слишком широкие шаблоны в `isCancelError` и `isModalBusyError`

- **Где:** `src/plugin/ps-bridge.js:57–68`.
- **Сценарии.**
  - Ошибка Photoshop «…only allowed from inside a modal scope» (например, от `encodeImageData` вне модального режима) содержит слово `modal` и показывается как «Photoshop занят другой операцией».
  - Любая ошибка со словом `cancel` в тексте считается отменой пользователем: панель пишет «Операция отменена», и ошибка не попадает в «Последнюю ошибку» диагностики (`panel.js:696`).
  - Если `executeAsModal` оборачивает исключение в новый объект, флаг `halationNothingToDo` теряется, и «нечего обрабатывать» показывается как «Ошибка: …».
- **Исправление.** Для «занят»: `/modal state|is busy|занят/i`. Для отмены: собственный флаг, `number === -128` или `ctx.isCancelled` (запоминать его в `stats` внутри модальной функции), а не слово в тексте. Для «нечего обрабатывать»: запоминать вид исхода в переменной замыкания `apply`, а не только в свойстве ошибки.

### М3. `layer.move` вызывается, когда слой уже стоит на месте

- **Где:** `src/plugin/ps-bridge.js:817–820`.
- **Суть.** В обычном случае активен исходный слой, `createPixelLayer` создаёт слой прямо над ним, и `move(src, PLACEBEFORE)` ничего не меняет. Для режима композита такая проверка есть (строка 823), для слоя — нет. Документация (`layer.md`) о перемещении «на то же место» молчит; проверить без Photoshop нельзя. Если Photoshop отвечает на это ошибкой, не сработает ни одно применение.
- **Исправление.** Перед `move` проверять положение: найти родителя `src` (`src.parent ? src.parent.layers : doc.layers`) и пропускать вызов, если новый слой уже стоит на индексе `indexOf(src) − 1` в том же списке. Пункт в чек-лист Ильи: первое применение при активном исходном слое.

### М4. Вызовы функций на пиксель в предпросмотре и ветвления в цикле прохода 2

- **Где:** `src/core/preview.js:274–283` (`S.combine` / `S.haloOnly` / `encode` на каждый канал каждого пикселя, `splatWeights` в `previewFields`), `src/core/processor.js:187–253` (`comps === 4` и `ex` проверяются на каждом пикселе, `NDX[k]` читается из массива).
- **Суть.** Раздел 5.7 требует циклы без вызовов функций. Полный пересчёт предпросмотра в `--jitless` — 1,67 с при цели 0,5 с; цель закрыта только черновым режимом (0,39 с).
- **Исправление.** В `renderPreview` развернуть `combine` и двоичный поиск в теле цикла (или искать код от соседнего, как в `pass2`). В `pass2` вынести `comps === 4` и `ex` за цикл по x (две-четыре копии цикла), `NDX` — в локальные константы. Ожидаемый выигрыш — 10–20 % прохода 2.

### М5. Пробелы в тестах, через которые проходят ошибки выше

- Поддельный `putPixels` не моделирует `replace` (Б1), `move` не проверяет порядок слоёв без замены (С3).
- Предпросмотр сверяется с полным расчётом только по линейным полям и только для непрозрачных картинок (С1, С2).
- Нет теста повторного применения в режиме композита без замены (С4) и теста «ошибка чтения одной полосы посередине» (С5).
- Независимость от высоты полосы проверяется только на базовом уровне 0. Проверка ревьюера на уровнях 0, 1, 2, нечётных размерах, 1×N, N×1 и с альфой расхождений не нашла — такой тест стоит добавить в набор.
- Тест панели не покрывает двойной щелчок (М1).

## Риски, которые нельзя проверить без Photoshop

Это не найденные ошибки, а места, где код опирается на непроверенное поведение. Каждое стоит включить в чек-лист.

1. **RGB прозрачных пикселей.** От того, что `getPixels` возвращает в RGB при α = 0, зависит величина ошибки С2.
2. **`globalThis` и `window`.** Все модули вешают глобальные имена на `globalThis`, а `panel.js:97–101` читает их с `window`. Если в UXP это разные объекты, панель покажет «Не загружено ядро». Страховка: в обёртках и в `tools/bundle-core.mjs:37` предпочитать `window`, если он определён.
3. **Ошибка `getPixels` для полностью прозрачной полосы.** Код принимает оба варианта ответа (исключение и пустой результат); какой из них настоящий, покажет диагностика («терпимых ошибок чтения»).
4. **`imaging.createImageDataFromBuffer` и `encodeImageData` вне модального режима** (`ps-bridge.js:1031–1046`) — запасной путь показа предпросмотра; при отказе панель покажет заглушку.
5. **Формат событий `addNotificationListener`** (`ps-bridge.js:1079–1088`): массив строк. При отказе предпросмотр просто не будет помечаться устаревшим; ошибка пишется в журнал.

**Ядро**
- Кривые: sRGB, сплайн PCHIP, концы (0,0) и (255,1), проверка строгого возрастания `LUT_in` в float32, обратный перевод по `LUT_in` с дробью в линейном свете (`processor.js:217–224`), `v ≥ 1 → 255`.
- Правило «пиксель не изменился»: допуск 0,02 шага в линейном свете, для кода 255 берётся шаг 254.
- Ровные поля всех 256 кодов на уровнях 0, 1, 2 и размерах 64×64, 37×53, 130×70 при кривых со скачком до 10⁷ раз (`[[254, 1e-7]]`) и с почти плоским участком — без изменений.
- Детерминизм: результат не зависит от высоты полосы (1, 2, 3, 7, вся высота) на уровнях 0, 1, 2, для RGB и RGBA, размеры 37×53, 64×64, 1×40, 40×1, 5×3, 101×7.
- Альфа не меняется; пиксели с α = 0 копируются как есть; NaN и значений вне 0…255 нет.
- Пирамида: фильтр [1,3,3,1]/8 и билинейное увеличение сопряжены, центры пикселей согласованы; поправки дисперсии (1,5·4^j на уровень, `(F² − 1)/12 + F²·mean(u(1 − u))` для базовой сетки) посчитаны верно.
- Размытие: веса через erf нормированы; box с дробной шириной — индексы буфера и скользящей суммы без сдвига на единицу; суммы в double.
- Дизеринг: тайл 64×64 по абсолютным координатам документа, сдвиги каналов (0,0), (23,37), (41,11).
- Модель приложения D (`O = L + a·max(H − L, 0)`) одинакова в `settings.combine`, в цикле `pass2` и в «Только ореол».
- Память: базовая сетка ограничена 6 млн пикселей, уровень выбирается автоматически.

**Связка с Photoshop**
- Один `executeAsModal`, `suspendHistory` / `resumeHistory(id, true)`, исключения не глотаются и выходят наружу — откат делает Photoshop.
- Удаление прежнего результата и создание слоя — в том же шаге истории; слой создаётся после прохода 1 и размытия.
- `dispose()` для всех `PhotoshopImageData` в `finally` (чтение, запись, JPEG предпросмотра).
- Точки отмены и прогресс: после каждой полосы и каждого прохода фильтра; доли 10 / 35 / 55 %.
- Раскладка обрезанного `sourceBounds` в буфер полосы (`placeStrip`), запись по возвращённым границам (`targetBounds = {left, top}`), точная длина буфера для `createImageDataFromBuffer`.
- Чтение в профиле документа (`componentSize: 8`, без `colorProfile`), запись с той же строкой профиля.
- Чтение полосы композита в проходе 2 не задевает уже записанные полосы результата (области не пересекаются).
- Проверки перед запуском: RGB, 8 бит, профиль, тип слоя, маска, непрозрачность, режим, обтравка, пустой слой, версии 26.5–26.10.
- Палитра: `showColorPicker` в `executeAsModal` с `interactive: true`, устойчивый разбор ответа, исключение считается отменой.

**UXP**
- Canvas: только `fillRect`, `strokeRect`, линии и `arc`; `clearRect`, градиентов, `fillText`, трансформаций нет; подписи — HTML.
- Перетаскивание: `setPointerCapture` с запасным вариантом через `document`.
- `sp-slider` (`input` / `change`), `sp-radio-group` (значение берётся тремя способами), `sp-checkbox`.
- `ImageBlob` с запасным `encodeImageData`; `URL.revokeObjectURL` для старых адресов.
- `localStorage` одним JSON с номером схемы; при ошибке — значения по умолчанию.
- Стартовая логика в `show`; обработчик возвращается сразу (ограничение 300 мс для манифеста v5 соблюдено), есть страховочный таймер.
- CSS без grid и без `gap`.

**Манифест и сборка**
- `host` — объект, `minVersion` 24.4.0, `apiVersion` 2, разрешение только `clipboard`, иконки @1x / @2x на месте и нужного размера.
- `.ccx`: `manifest.json` в корне, без скрытых файлов и записей каталогов; запись во временный файл с переименованием.
- Бандл ядра: UMD с глобальным `HalationCore`, собственный `require` модулей, без `eval` и `new Function`; `dist/` совпадает с текущими исходниками.
