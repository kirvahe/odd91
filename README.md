# odd91: Halation для Photoshop

Плагин для Photoshop (UXP, чистый JavaScript), который добавляет плёночный ореол — halation — вокруг ярких мест.

- Работает с 8-битными sRGB-файлами, расчёт идёт в линейной гамме.
- Три режима перевода:
  - стандартная кривая sRGB;
  - своя кривая по точкам;
  - «8 бит → scene-linear»: обратный Reinhard, как 8-битный режим гизмо Halation для Nuke.
- Два метода:
  - «Без каймы» — `L + a·max(H − L, 0)`, по умолчанию;
  - «Proosa» — как в hotgluebanjo/halation-dctl.
- Настройки: цвет свечения, размытие, сила (до `a = 1`, уровень Proosa).
- Результат — новый слой «Halation», исходный не меняется.
- Полос при возврате в 8 бит нет: дизеринг синим шумом.
- Ставится без Creative Cloud: распакованную папку кладут в `Plug-ins`.

**Пошаговая инструкция с картинками:** [docs/install-guide-ru.html](docs/install-guide-ru.html). Она же лежит в архиве релиза: скачай, распакуй и открой в браузере. Техническая версия — [docs/install-ru.md](docs/install-ru.md).

## Сборка и проверка

```bash
npm test          # тесты ядра, связки с Photoshop (на подделке) и сборки
npm run build     # dist/dev.halation.photoshop_PS.ccx и распакованная папка
npm run bench     # замер скорости без JIT, как в Photoshop
```

Нужен Node 21+, зависимостей нет.

**Демо-страница:** `demo/index.html` — то же ядро в браузере, со своими картинками и тестовыми сценами. Чтобы она открылась, нужен локальный сервер из корня проекта, например `python3 -m http.server`, и предварительно `npm run bundle`.

## Устройство

| Папка | Что внутри |
|---|---|
| `src/core/` | Ядро: кривые, пирамида размытия, два прохода полосами, предпросмотр, дизеринг. Без зависимостей от Photoshop; контракт — `src/core/API.md` |
| `src/plugin/` | Панель UXP и связка с Imaging API |
| `tools/` | Сборка ядра и `.ccx`, генерация синего шума и иконок, замер |
| `test/` | Тесты (`node --test`) |
| `docs/` | Проектный документ, исследования, ревью, инструкция |

Модель ореола: `O = L + a·max(H − L, 0)` в линейном свете. `H` — свет, размытый ядром из двух экспонент. Почему так, а не нормировкой `(L + a·H)/(1 + a)`, — см. приложение D проектного документа.
